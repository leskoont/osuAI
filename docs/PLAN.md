# План отладки и доработок OsuAI

Документ фиксирует аудит исходной версии (коммит `initial`), найденные ошибки и то,
как каждая из них закрыта в версии 2.0. Целевое железо: **i5-10400 (6C/12T), RTX 2060 6 GB, 32 GB RAM, Windows**.

## 1. Как работала исходная версия

```
main loop (один поток):
  capture() 2560x1440 → PIL → numpy RGB               ─┐ весь экран, дважды за кадр
  capture_preprocessed() → ещё один снимок → 256x256 ─┘
  model.predict() (Keras, 30M параметров)             ← ~20-50 мс оверхеда
  detect_hit_circles + HoughCircles (для отрисовки)    ← на полном 1440p
  parse_game_stats → 3× Tesseract OCR                  ← по 50-200 мс каждый
  execute_action: 3 способа движения мыши + sleep 20 мс + sleep 10 мс на клавишу
  calculate_reward → ещё раз OCR ×3, детекторы ×2
  memory_buffer.append(float64 256x256)
поток обучения: fit(states, actions * rewards)
```

Реальная частота — единицы кадров в секунду, а обучение не могло сойтись в принципе.

## 2. Найденные ошибки

### Критические (агент не мог научиться)
| # | Проблема | Где | Исправление |
|---|----------|-----|-------------|
| 1 | Цель обучения `target = action * reward` — не RL, а регрессия всех выходов к нулю (курсор уезжает в угол, клавиши перестают нажиматься) | `neural_network.train` | Double-DQN с n-step возвратами, target-сетью и Huber-loss (`osuai/learner.py`) |
| 2 | Награда обрезана в `[0, 1]` — промахи и спам не наказывались | `calculate_reward` | Награды со знаком: ±1 за 300/miss, штраф за спам (`osuai/reward.py`) |
| 3 | Нет исследования: сеть детерминированно повторяет свои выходы | `main` | ε-greedy + «подсказки» детектора (guided exploration) |
| 4 | Награда приписывается кадру, а не нажатию, которое её вызвало | `calculate_reward` | `CreditAssigner`: задержка коммита в replay и привязка событий к нажатию |
| 5 | Клавиши только «тапаются» (down-sleep-up) — слайдеры держать невозможно | `input_controller.press_key` | Состояние «зажата/отпущена», чередование клавиш |
| 6 | Нет информации о движении: на входе один кадр — нельзя понять, сжимается approach circle или нет | `capture_preprocessed` | Стек из 4 кадров + признак зажатой клавиши |

| # | Проблема | Исправление |

| 7 | Кадр в RGB, а детектор делает `BGR2HSV`/`BGR2GRAY` — цвета перепутаны; `imshow` тоже показывает RGB как BGR | Везде BGR(A), конверсий нет |
| 8 | TensorFlow ≥ 2.11 **не поддерживает GPU на нативной Windows** — `tensorflow==2.13` всё считал на CPU, RTX 2060 простаивала | Переход на PyTorch + CUDA |
| 9 | Гонка потоков: обучение (`fit`) и инференс (`predict`) одной Keras-модели одновременно; `list.pop(0)` из буфера во время чтения | Отдельные модели актора и learner, синхронизация весов под lock, lock-free replay с одним писателем |
| 10 | Разрешение 2560x1440 захардкожено, смещение выбранного монитора не учитывается — курсор уезжает на другом мониторе/разрешении | Область захвата из клиентской области окна osu!, координаты виртуального рабочего стола |

## 3. Архитектура версии 2.0

```
поток capture ──(dxcam/mss → resize → uint8 96x128 + цветной 256x192)──► последний кадр
поток tosu    ──(WebSocket: 300/100/50/miss, комбо, состояние)──────────► последнее состояние
актор (60 Гц, основной поток):
   кадр → стек 4 кадров → CUDA Graph (high-priority stream) → ε-greedy/подсказка → SendInput
   → шейпинг-награда + события tosu → CreditAssigner → ReplayBuffer (uint8)
поток prefetch ── батч из replay (+демо) → pinned-буфер
поток learner  ── H2D uint8 → fp16 autocast Double-DQN (+DQfD margin) → fused Adam
                   → polyak target → публикация весов (fp16) → актор забирает раз в секунду
поток vis      ── окно отладки 15 Гц: вход сети, Q-карта, детекции, статистика
```

**Пространство действий** — Q-карта 2×24×32 поверх области захвата: для каждой ячейки
«курсор сюда + держать/не держать клавишу». Сеть полностью свёрточная, поэтому то, что
она выучила в одном месте экрана, сразу работает во всех остальных.

**Награды.** Основной источник — [tosu](https://github.com/tosuapp/tosu) (или gosumemory):
точные попадания из памяти игры. Детектор кругов даёт плотную эвристику (близость курсора к
самому срочному кругу, штраф за клики мимо) и «учителя» для исследования. Без tosu агент
учится только на эвристике — медленнее и хуже.

**Демонстрации (DQfD).** `record` пишет вашу игру; `pretrain` обучает на ней
(TD + large-margin loss), затем `train` доучивает с подмешиванием демо в батч.

## 4. Оптимизации под i5-10400 + RTX 2060

* **GPU (Turing, sm_75)**: fp16 autocast + GradScaler (bf16 на Turing нет), `channels_last`,
  `cudnn.benchmark`, fused Adam, foreach-операции, CUDA Graph для инференса batch=1.
* **Приоритеты на GPU**: актор на CUDA-потоке с высоким приоритетом, learner — с низким;
  обучение не увеличивает задержку реакции.
* **PCIe**: батчи едут на GPU в uint8 (в 4 раза меньше, чем fp32), из pinned-памяти, асинхронно.
* **Нет синхронизаций CPU↔GPU в цикле обучения**: метрики копятся на GPU, читаются раз в 2 с.
* **CPU**: `torch.set_num_threads(4)`, `cv2.setNumThreads(2)` — остаётся запас ядер для osu!;
  `sys.setswitchinterval(1 мс)` вместо 5 мс, чтобы фоновые потоки не задерживали актора;
  `timeBeginPeriod(1)` и точный `sleep_until` для ровного шага 60 Гц; приоритет процесса above normal.
* **RAM**: replay 400k шагов ≈ 4.6 GB; кадры не дублируются в стеке и в next-state.
* **Нагрузка**: при 60 Гц и `replay_ratio=0.5` нужно 30 апдейтов/с — RTX 2060 делает в разы больше
  (проверьте `python main.py benchmark`), остаток GPU остаётся osu!.

## 5. Порядок отладки на реальной игре

1. `python main.py benchmark` — проверить, что torch видит GPU (`sm_75` в сборке) и скорость.
2. `python main.py train --sim` — убедиться, что весь конвейер учится в симуляторе (точность
   растёт в `logs/episodes.csv`).
3. Настроить osu!: оконный/borderless режим, **Background dim 100%**, выключить видео/сториборды,
   **выключить Raw input**, ограничить FPS osu! (например, 240), клавиши Z/X (или `--keys`).
4. Запустить tosu, открыть карту, `python main.py play` → в окне «OsuAI Vision» проверить, что
   область захвата совпадает с playfield, детектор видит круги, курсор двигается туда, куда нужно.
   При смещении поправить `capture.playfield_y_offset` / `margin_*` или задать `manual_region`.
5. `python main.py record --out demos/run1.npz` — записать 10-20 минут своей игры на лёгких картах.
6. `python main.py pretrain --demos "demos/*.npz"` → `python main.py train --demos "demos/*.npz"`.
7. Следить за `logs/episodes.csv` (точность, промахи) и строкой статуса (latency p99 < 16 мс).

## 6. Что можно сделать дальше

* Слайдеры и спиннеры в симуляторе (сейчас только круги).
* Prioritized replay; распределительный (C51/QR) выход; sub-cell регрессия позиции курсора.
* Компенсация задержки: предсказывать действие на Δt вперёд по `hitErrorArray` из tosu.
* Экспорт актора в TensorRT (ещё ~2x к инференсу, но ограничения на обновление весов).
